# 🛡️ AWS Security Hub Overview

## 🧩 Definition

**AWS Security Hub** is a centralized service that consolidates **security findings and alerts** from various AWS accounts and provider products into a **single dashboard**.

It allows users to:

- 🚨 Manage security alerts.
- 🤖 Automate security checks.
- 🛠️ Respond to security issues efficiently.

---

## 🔗 Integration with AWS Services

AWS Security Hub integrates with multiple AWS services, including:

- 🛡️ **Amazon GuardDuty**
- 🔍 **Amazon Inspector**
- 🔐 **Amazon Macie**

Security Hub also supports integrations with **third-party security solutions** from AWS Partner Network members.

It supports **over 60 integrations** with security vendors such as:

- 🏢 **Symantec**
- 📊 **Splunk**
- 🛡️ **Palo Alto Networks**

---

## 📋 Security Standards and Best Practices

AWS Security Hub implements security best practices and standards, including:

- 🛡️ **AWS Foundational Security Best Practices**
- 📋 **CIS AWS Foundations Benchmark**
- 💳 **PCI DSS**

Security Hub provides a **security and compliance score** based on these benchmarks.

This helps users identify areas that require attention.

# 🛡️ AWS Security Hub Standards Overview

## 🧩 Definition

**AWS Security Hub** implements three key security standards to enhance security and help organizations monitor compliance:

1. 🛡️ **AWS Foundational Security Best Practices**
2. 📋 **CIS AWS Foundations Benchmark**
3. 💳 **PCI DSS**

These standards provide security requirements and best practices that can be monitored through AWS Security Hub.

---

## 🛡️ AWS Foundational Security Best Practices

**AWS Foundational Security Best Practices Version 1.0** includes basic security actions such as:

- 🔐 Enabling **Multi-Factor Authentication (MFA)**.
- 🔑 Setting **strong password policies**.
- 🪣 Ensuring **Amazon S3 buckets are not publicly accessible**.

These practices help establish a strong security foundation for AWS environments.

---

## 📋 CIS AWS Foundations Benchmark

**CIS AWS Foundations Benchmark Version 1.2** focuses on **AWS configuration best practices**.

It emphasizes:

- 👀 **Monitoring**
- 📝 **Logging**

These practices help organizations identify potential security issues within their AWS environment.

---

## 💳 PCI DSS

**PCI DSS Version 3.2.1** focuses on the secure handling of **credit card information** within AWS.

It provides security requirements for environments that handle payment card information.

# 🔐 AWS IAM Security Best Practices Overview

## 🧩 Definition

AWS Identity and Access Management (**IAM**) security best practices help protect AWS accounts and resources by following secure access management principles.

Key practices include:

- 🔐 Protecting the root user with **Multi-Factor Authentication (MFA)**.
- 👥 Using groups to manage administrator permissions.
- 🎭 Using roles for temporary permissions.
- 🛡️ Following the **Principle of Least Privilege**.
- 🚫 Avoiding access keys stored directly in code.

---

## 🔐 Protect the Root User

Assign **Multi-Factor Authentication (MFA)** to the **root user** to provide additional protection for the AWS account.

MFA adds an additional security layer when accessing the root account.

---

## 👥 Use Groups for Administrator Permissions

Create an **IAM Group** with administrator permissions and add users to the group instead of assigning administrator permissions directly to individual users.

This provides:

- 👥 Centralized permission management.
- 📜 Easier permission administration.
- 🔄 Simplified management of multiple users.

---

## 🎭 Use Roles for Temporary Permissions

Use **IAM Roles** to grant **temporary permissions**.

Roles help follow the **Principle of Least Privilege**, ensuring users and services receive only the permissions they need.

Roles are primarily used for:

- ⚙️ Service interactions.
- 🖥️ EC2 instances.
- 🔄 AWS services.

Roles should only have the **necessary permissions** required to perform their tasks.

---

## 🚫 Do Not Store Access Keys in Code

Do **not** store AWS access keys directly in code.

Avoid storing access keys in:

- 🖥️ **EC2 instance code**
- 🪣 **Amazon S3 buckets**

Storing access keys in code can expose credentials and create security risks.
